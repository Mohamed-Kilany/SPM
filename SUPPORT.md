# Support

## Community support

Use GitHub Issues for reproducible bugs and feature requests:

- [Bug report](https://github.com/Mohamed-Kilany/SPM/issues/new?template=bug_report.yml)
- [Feature request](https://github.com/Mohamed-Kilany/SPM/issues/new?template=feature_request.yml)
- GitHub Issues for usage questions tagged `question`.

This is a self-hosted, offline-first project. Community support is best-effort and has no
response SLA. Include the commit or version, deployment method, relevant sanitized logs and the
steps that reproduce the problem. Never paste secrets, tokens, customer data or `.env` content
into an issue.

## Security reports

Do not open a public issue for a vulnerability. Use the private process in
[`SECURITY.md`](SECURITY.md).

## Supported versions

`master` is the only supported line until releases are tagged. See
[`SECURITY.md`](SECURITY.md) for the support policy and response targets.

## Commercial and air-gapped deployments

Installation and upgrade guidance for disconnected environments is tracked as `OPS-02` and
`OPS-12` in [`TASKS.md`](TASKS.md). Until those runbooks are verified, no air-gapped support
claim is made. Contact the maintainer through the repository profile for deployment questions
that cannot be discussed publicly.
